# CIX 黑客松 — 演示场景 & PPT 大纲

## 项目定位

**SimpleFileManager — 你的私人 AI 数据管家**

本地 NAS + 20B 模型 + 隐私优先，不连云即可完成文件搜索、整理、清理和问答。

---

## 演示场景

以下场景均已在实机上测试通过。演示时建议按顺序播放，每个场景 30-60 秒。

---

### 场景 1: 语义搜文档 — "我忘了文件名，但记得内容"

**钩子**: 用户不记得文件叫什么，只记得里面写了什么。

**操作**:
```
用户: 帮我搜一下有"押一付三"的文件
模型: 调用 search_files → 找到 contract.txt（租房合同）
```

**演示要点**:
- 模型自主调用 `search_files` 工具
- 找到包含关键词的文本文件
- 返回文件路径 + 内容摘要

**实机记录**:
```
工具调用: search_files({'query': '押一付三', 'limit': 20})
结果: contract.txt (租房合同)
```

---

### 场景 2: 散落文件 — 一键整理

**钩子**: 下载文件夹/根目录乱七八糟，按类型自动归类。

**操作**:
```
用户: 根目录很乱，请按文件类型整理：合同类、计划类、财务类、会议类
模型: 调用 list_directory → create_directory → move_file → file_info
```

**演示要点**:
- 模型先扫描目录（`list_directory`）
- 创建分类子目录（`create_directory`）
- 移动文件到对应目录（`move_file`）

**实机记录**:
```
工具调用序列:
1. list_directory → 扫描根目录
2. create_directory("合同类")
3. create_directory("财务类")
4. create_directory("会议类")
5. create_directory("会议纪要")
6. move_file("contract.txt" → "合同类/")
7. move_file("budget_2024.txt" → "财务类/")
... 等
```

---

### 场景 3: 重复文件清理 — "NAS 里有多少重复？"

**钩子**: 同一份文件被保存了多次，浪费空间。

**操作**:
```
用户: 帮我找出重复的文件
模型: 调用 list_directory → search_files → read_file → 对比内容
```

**演示要点**:
- 模型扫描并对比文件内容
- 识别出 `contract.txt` / `contract_backup.txt` 和 `budget_2024.txt` / `budget_2024_copy.txt` 是重复
- 列出重复项等待用户确认删除

**实机记录**:
```
工具调用序列:
1. list_directory → 扫描
2. search_files → 找同名/相似文件
3. read_file → 对比内容确认重复
```

---

### 场景 4: 权限管控演示 — 关闭删除工具

**钩子**: 管理员可以精确控制 Agent 不能做什么。

**操作**:
```
管理员: 在设置中关闭 delete_file 工具
用户: 请删除 contract_backup.txt
模型: 无法删除 → 告知用户没有删除权限
```

**演示要点**:
- 设置页工具面板中，关闭 `delete_file`（标记为"危险"红色）
- 模型再也看不到这个工具
- 即使模型想删除，也无法调用

**实机记录**:
```
关闭 delete_file 后:
工具调用: search_files → move_file → file_info → list_directory
模型无法调用 delete_file，只能尝试其他方式
```

---

### 场景 5: 自定义 Skill — 上传一个"做演示文稿"技能

**钩子**: 用户可以教 Agent 新的工作方式。

**操作**:
```
管理员: 在设置中新增技能:
  ID: make_ppt
  名称: 做演示文稿
  指令: "做 PPT 时，先搜索素材文件，读取内容，整理结构后生成演示文稿。"

用户: 帮我做一份项目进度的 PPT
模型: 注入 skill 指令 → 按方法论调用 read/write/search 工具
```

**演示要点**:
- 设置页 "+ 添加自定义技能" 表单
- 输入 ID、名称、指令
- 保存后该技能的指令会在模型上下文注入
- 模型按这个方法论自由选择工具

## 系统架构（给评委快速理解）

```
┌──────────────────────────────────────────────────┐
│                  Web 前端 (React)                 │
│  设置页: 技能总开关 | 逐技能开关 | 逐工具开关     │
└──────────────────────┬───────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────┐
│              FastAPI 后端                         │
│                                                  │
│  Skills Engine                                   │
│  ├─ Skill Registry (内置 + 用户上传)             │
│  ├─ Tool Gating (按开关过滤)                     │
│  ├─ System Prompt Builder (注入技能指令)         │
│  └─ Tool Calling Loop (max 8 rounds)            │
│                                                  │
│  ┌─────────────────────────────────────────┐    │
│  │  Base Tools (始终可用)                   │    │
│  │  search_files / list_directory           │    │
│  │  read_file / write_file                  │    │
│  ├─────────────────────────────────────────┤    │
│  │  Atomic Tools (按开关暴露)               │    │
│  │  move_file / delete_file / create_dir    │    │
│  │  file_info                               │    │
│  └─────────────────────────────────────────┘    │
│                                                  │
│  本地 20B 模型 (llama-server, OpenAI-compatible) │
└──────────────────────────────────────────────────┘
```

---

## 三层控制模型

| 层级 | 控制什么 | 谁操作 |
|------|---------|--------|
| 技能总开关 | 是否启用技能系统 + 原子工具 | 管理员 |
| 单个技能 | 是否注入该技能的方法论 | 管理员 |
| 单个工具 | 是否暴露该工具给模型 | 管理员 |

## PPT 大纲 + 每页表述稿

---

### 第 1 页 — 封面

**标题**: SimpleFileManager — 你的私人 AI 数据管家

**副标题**: 本地 NAS × 20B 模型 × 隐私优先，不连云的 Agent 文件管理

**口述**:
> "大家好，今天介绍的是一个跑在 Orange Pi 上的家庭 NAS 文件管理器。它的核心特点是：你的数据永远在你的硬盘上，AI 模型也是本地的 20B 参数模型，但 Agent 能力让你可以像聊天一样管理文件。"

---

### 第 2 页 — 问题

**标题**: 公有云方案的三大痛点

| 问题 | 说明 |
|------|------|
| 隐私 | 文件上传到云端，受制于服务商政策 |
| 成本 | iCloud/Google Drive 月订阅，长期昂贵 |
| 功能固定 | 厂商给什么用什么，不能自定义 |

**口述**:
> "现在大家存文件要么用 iCloud 要么用 Google Drive。但你的家庭照片、合同、孩子的作业——这些隐私数据要上传到别人的服务器。而且每月都要付费。更重要的是，厂商给你什么功能你就用什么功能，你没法教它'帮我按日期整理照片'。"

---

### 第 3 页 — 解决方案

**标题**: 本地 NAS + 本地 AI = 数据主权 + 可定制

| 维度 | 公有云 | SimpleFileManager |
|------|--------|-------------------|
| 数据位置 | 云端服务器 | **你的硬盘** |
| 运行成本 | ¥50-200/月 | **一次硬件投入** |
| 隐私 | 服务商可访问 | **零出境** |
| 功能 | 固定 | **可定制 Agent 技能** |
| AI 能力 | 需联网 API | **本地 20B 模型** |

**口述**:
> "我们的方案是把 NAS 和 AI 模型都放在家里这台小机器上。Orange Pi Pro 搭载 CIX P1 CPU，本地跑一个 20B 参数的模型。所有文件分析、搜索、整理全部在本地完成。没有月费，数据不出你家门。"

---

### 第 4 页 — 产品演示

**标题**: 用自然语言管理文件

**截图/录屏**: 5 个场景的录屏拼接

1. 语义搜文档（搜"押一付三"找到合同）
2. 散落文件一键整理
3. 重复文件识别
4. 关闭 delete_file 后模型无法删除
5. 自定义"做演示文稿"技能

**口述**:
> "你不需要记住文件名，只要记得内容就能找到。AI 会自动搜索、整理。你还可以自定义技能——比如教它'怎么做 PPT'，它就会按你的方法论去调用工具。"

---

### 第 5 页 — 技术架构

**标题**: Skills 系统 — 方法论 × 工具的分离

**图示**: 三层控制模型

**口述**:
> "技术上的核心创新是 Skills 系统。它把'怎么做'和'能做什么'分开。技能是方法论——比如'整理文件要先扫描、分类、移动'，模型自己选工具。工具是原子能力——搜索、读取、移动、删除。两层都可以独立开关，管理员有完全的控制权。"

---

### 第 6 页 — 安全设计

**标题**: 权限粒度可控，危险操作可锁

**图示**: 工具面板截图（delete_file 红色标签 + 开关）

| 工具 | 风险等级 | 默认状态 |
|------|---------|---------|
| search_files | 安全 | 开启 |
| list_directory | 安全 | 开启 |
| read_file | 安全 | 开启 |
| write_file | 一般 | 开启 |
| create_directory | 一般 | 开启 |
| move_file | 谨慎 | 关闭 |
| delete_file | **危险** | **关闭** |

**口述**:
> "安全上我们做了三层控制。最细可以到单个工具——比如 delete_file 标记为红色危险，默认关闭。管理员可以选择性地只开放移动，不开放删除。模型看不到被关闭的工具，从根本上杜绝越权。"

---

### 第 7 页 — 商业价值

**标题**: 不只是家庭工具，是小企业的合规基础设施

**三个市场**:

1. **家庭用户**: 照片档案、家庭财务、孩子成长记录 — 情感价值高，隐私敏感
2. **自由职业者 / 小工作室**: 合同管理、项目文档、作品归档 — 替代月订阅网盘
3. **隐私敏感行业**: 律师、心理咨询师、财务顾问 — 行业合规要求数据不出本地

**口述**:
> "家庭用户是最直接的——谁都不想把自己的照片上传到云端。但更大的市场是小企业和自由职业者。律师和心理咨询师有合规要求，客户资料不能上云。这套方案就是为这些人设计的。"

---

### 第 8 页 — 总结

**标题**: 你的数据，你的 AI，不连云

**三句话**:
- 数据主权 — 文件永远在你的硬盘
- 可定制 — 技能系统让 Agent 按你的方式工作
- 隐私优先 — 本地 20B 模型，零数据出境

**口述**:
> "总结一下：这是一个跑在 200 美元硬件上的私有 AI 文件管理器。你的数据在你家里，AI 按你的方式工作，不需要任何月费。谢谢大家。"
