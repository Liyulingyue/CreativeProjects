## 演示前 60 秒检查清单

```bash
cd /home/orangepi/Codes/CreativeProjects/SimpleFileManager

# 1. 拿一个会话令牌（用演示机上的管理员账号密码）
TOKEN=$(curl -s -X POST http://127.0.0.1:8000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"<管理员账号>","password":"<密码>"}' \
  | python3 -c "import json,sys; print(json.load(sys.stdin).get('token',''))")
echo "token 长度: ${#TOKEN}"

# 2. 服务齐活（应当 5 个 200）
for p in 9010 9011 9012 9013 9014; do
  printf "%s:" $p; curl -s -m 3 -o /dev/null -w "%{http_code} " http://127.0.0.1:$p/v1/models
done; echo

# 3. jina 带着视觉投影器（vision: true 才对）
curl -s http://127.0.0.1:9014/props | python3 -c \
  "import json,sys; d=json.load(sys.stdin); print('vision:', d['modalities']['vision'])"

# 4. 图片索引：既要有东西，也不能正在建
curl -s http://127.0.0.1:8000/api/images/index/status -H "Authorization: Bearer $TOKEN" \
  | python3 -c "import json,sys; d=json.load(sys.stdin); print('已索引', d['indexed'], '张 | 正在构建:', d['running'], '| 失败:', d['failed'])"
```

**第 4 条两个数都要看**：
- `已索引` 是 0 → 先点「建立图片索引」（一张图 3 秒，四张十几秒）
- `正在构建` 是 True → **先等它跑完或暂停**。构建期间每张图占住大核 3 秒，搜图会等到 3 秒甚至直接说「服务器正在忙」，演示会难看。

| 缺什么 | 怎么办 |
|---|---|
| 9014 没起来 | `./LLMServices/serve.sh start-jina`（模型和投影器在 `LLMServices/models/jina-v5-omni/`） |
| `vision: false` | 投影器路径不对，检查 `serve.sh` 里的 `JINA_MMPROJ`（要用 `-64tok` 那份） |
| 索引是 0 张 | 搜索页点「建立图片索引」，或等 09:00–09:30 的定时窗口 |
| 后端没起 | `./run_dev.sh --restart backend` |
| **聊天报 402 / 额度用尽** | **聊天页的 provider 下拉必须选本地 `Model24B`**。默认的主 provider 是远程 LongCat，额度常常已经用尽 |

3. **把定时窗口挪走。** 默认是每天 **09:00–09:30** 自动建索引 —— 如果演示正好在这个时间段，**没人点任何按钮，大核也会被占住 30 分钟**，而这不可控。演示前把它改成一个不会命中的时段：

```bash
curl -s -X POST http://127.0.0.1:8000/api/settings -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"image_index_enabled": false}'
```

**还有两件容易忘的**：

1. **上传完图片要重建一次索引。** 上传只会把文件放进存储目录，**新图不会自动进向量表**——必须点一次「建立图片索引」（或等下一个 09:00 窗口）。这一步是「上传几张图 → 找一张红色的苹果」这条主线的必经环节。
2. **先做一次搜图把缩略图缓存热起来。** 缩略图是服务端现算的，第一次要解码原图；先跑一次，演示时页面出图就是瞬时的。

**准备几张有代表性的图**：一张红苹果、一只猫、两张日落（一张海边、一张希腊）。文件名故意起得不好认（比如 `IMG_20240713_182233.jpg`），正好体现「靠画面找文件」。把它们放进存储根的任意目录，再点一次「建立图片索引」。

（仓库里的 `backend/data/` 是 gitignore 的，样图不会跟着代码走，演示前要自己准备。）

## 场景 A — 以文搜图（40 秒）

**屏幕**：搜索页 `/search` → 顶部切到「图片」标签

**话术**：

> 「我的照片有一千张，文件名全是 `IMG_20240713_182233.jpg` 这种。我记得里面有一张海边的日落，但我不知道它叫什么。」

**操作**：
1. 在输入框写：`海边日落`
2. 回车 → 约 0.15 秒出结果，缩略图网格，按相似度排序

**注意**：实测这两张日落（`Sunset_in_Greece` 与 `Beach_sunset`）分数很接近（0.51 / 0.47），排第一的未必是"海边"那张。想让演示结果无歧义，搜 `一只可爱的猫` 或 `一张红色的水果` —— top-1 稳赢第二名三倍。

**要说的三点**：
- 「这个模型叫 jina-embeddings-v5-omni，它把**文字和图片放进同一个向量空间**，所以一句话能直接匹配一张图」
- 「整个过程 0.15 秒，**没有联网，没有上传**，图片一个字节都没离开这台机器」
  （前提是此刻没有图片索引在跑——这也是为什么演示前要确认状态栏那一行）
- 「用的是 200 美元的机器 —— 8 个大核跑 24B 模型，4 个小核跑向量库」

**可加演的追问**（挑一个）：
- 「换成 `一张红色的水果`」→ 命中苹果
- 「一只可爱的猫」→ 命中猫
- 「日落」也能搜到希腊那张 —— 同一个概念，不同措辞

## 场景 B — 以图搜图（30 秒）

**屏幕**：搜索页 → 图片标签

**操作（两种 ways，任选其一）**：

1. **页面上直接点**：搜出结果后，每张图下面有「找相似」→ 画面变成「以图搜图：和 Red_apple.jpg 最像的 4 张」，原图标成「参考图」
2. **让模型做**（更能体现 agent 的能力）：在 Agent 对话页 `/chat` 里问
   > 「找一张和 `照片测试/Red_apple.jpg` 长得像的图片」

**模型会做的事**：`find_similar_images` 工具 → 编码这张图 → 找最近的邻居 → 回答里列出路径

**要说的**：
- 「同一张表，同一个模型，**零额外成本**」
- 「模型看不见图 —— 它只能告诉你路径，所以真正的价值在**缩略图网格**；页面上那一下『找相似』，走的是同一个接口」

## 场景 C — 图片索引的定时窗口（20 秒，讲设计）

**屏幕**：设置页 → 「图片索引」卡片

**话术**：

> 「一张图要占 3 秒大核，而这些核正是模型要用的。所以图片索引不是后台常驻，而是**每天早 9 点到 9 点半这个窗口里跑**，到点就停，哪怕没做完。下次窗口接着做 —— 已经编好的图按内容哈希跳过。」

**可现场验证**（如果时间充裕）：把窗口改成当前时间起 1 分钟 → 观察状态栏的进度条 → 到点它自己停。

**顺序很重要**：这个演示会真的启动一次构建，而构建期间搜图会变慢（约 3 秒）甚至失败。**所以场景 C 放最后**，演示完立刻点「暂停」，或者把窗口改回一个不会命中的时间段。

## 兜底话术

| 情况 | 说什么 |
|---|---|
| 搜图报「服务器正在忙」 | 「这是设计如此：搜图和模型抢同一批核，服务器只肯等 **8 到 20 秒**（按刚测出的单张编码时间算），不排队。**在等的人不该排队**，这是这个盒子最重要的取舍之一。」 |
| 索引是空的 | 「图片索引要单独建 —— 文本索引是常驻的，图片索引是显式的，因为一张图要 3 秒。」 |
| 缩略图加载慢 | 「缩略图是服务端现算的缓存，第一次点会慢一点。」 |

## 技术问答备用

| 评委可能问 | 答案 |
|---|---|
| 为什么不用 OCR？ | OCR 能搜文字，但不能搜「画面像什么」。这里是**向量检索**，文字和图片同构。 |
| 一万张图要多久？ | 3 秒/张 ≈ 8 小时。所以要分窗口跑，这也是设计的一部分。 |
| 精度够吗？ | 实测 64 token 预算下 top-1 全对（苹果/猫/两张日落）。把分辨率提上去更准，但慢 4 倍。 |
| 会不会把图片传出去？ | 不会。jina 服务跑在 `127.0.0.1:9014`，图片 base64 只在本机进程之间流动。 |
| 为什么要大核锁？ | 模型、搜图、图片索引三者抢同一批核。锁保证同一时刻只有一个在跑 —— 演示时**模型生成期间搜图会直接拒绝**，而不是让模型掉速。 |
| 缩略图那张 0.37 的「相似度」是什么？ | jina 空间里的余弦相似度，不是概率。 |
