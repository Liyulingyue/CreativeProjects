# 前端测试

真浏览器里的测试：playwright 驱动真的页面，检查真的行为。

```bash
SFM_PASSWORD=你的密码 node tests/run.mjs
# 或者
npm test
```

需要前后端都在跑（`./run_dev.sh`）。

## 为什么不是 vitest

这个项目没有测试框架，也不需要装一个：playwright 已经在依赖里，
而且**在真浏览器里驱动真的页面**比在假 DOM 里挂一个组件更值得信。
框架只提供 `harness.mjs` 里的登录、几个断言和一个汇总。

## 有什么

| 文件 | 测什么 |
|---|---|
| `picture-search.test.mjs` | 搜图、排序、缩略图、找相似、服务器的错话 |
| `index-controls.test.mjs` | 建索引的按钮、管理员门控、「已经在跑了」 |
| `pages.test.mjs` | 设置页的图片索引卡片、文本搜索、Agent 对话 |
| `file-manager.test.mjs` | 文件列表、删除按钮的禁用、右键重命名真的改了名字 |
| `upload-trash.test.mjs` | 上传的文件出现在列表里、删掉进回收站、还原真的回来了 |
| `chat.test.mjs` | 答案一个字一个字地出来、别的会话里看不到、离开页面回来答案还在、下拉里选的模型不被换掉 |

共 35 个。

## 写测试时注意

- 状态是**轮询**的（5 秒一次）：改了 mock 之后要 `page.reload()`，
  否则屏幕上还是旧的状态。
- 用 `page.route()` 假装服务器说什么，用来测「服务器说忙」「不是管理员」
  这些平时很难造出来的情形。
- **要看见一个字一个字地出来，就得有一个真的在出字的服务器。**
  `page.route()` 只能一次给完，一给完这一轮就结束了，字也就没了。
  所以 `chat.test.mjs` 自己起了一个小 HTTP 服务器假装模型，
  后端、真的流、真的页面都在，只有模型是假的。
- 测试动了系统里的东西（provider 表），要在 `teardown` 里放回去，
  失败的那条也会走 `teardown`——不然下一次跑就会带着上一次的东西。
